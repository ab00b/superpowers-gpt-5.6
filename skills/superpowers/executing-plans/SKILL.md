# Executing Plans

A plan's existence or approval to plan does not authorize implementation. Without implementation authority, inspect and report only.

1. Read the plan, nearest `AGENTS.md`, and relevant repository state.
2. Track unfinished outcomes. Before tools, announce the first; update the user only at material phase changes with its result and the next outcome.
3. Batch small same-shape outcomes into one execution/review unit, retaining acceptance and verification per target. Separate work needing distinct judgment, tests, or risk; implement minimally.
4. After final changes, run required checks and compare the diff with acceptance.

Treat requirements and acceptance as authority; the plan argues how. Adapt mechanics to repository reality. Record material rulings, rationale, and cost if wrong; update durable plans only for material requirement, design, or verification changes.

Later mutations invalidate affected evidence; rerun it before claiming completion.

Resolve recoverable failures safely. Ask only for missing authority, consequential architecture, irreversible/external action, or when every safe path is guesswork.

Do not invoke another workflow skill solely because a plan exists.
